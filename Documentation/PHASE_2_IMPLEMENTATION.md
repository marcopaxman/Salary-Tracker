#### **FirestoreJob.kt**
- Firestore-compatible version of `Job`

- Includes timestamps
- Bidirectional conversion methods

**Key Features**:
- ✅ Auto-generated document IDs

#### **FirestoreMonthlyGoal.kt**
- Firestore-compatible version of `MonthlyGoal`
- Uses yearMonth string as document ID
- Stores goalTips and commissionPercent
- Bidirectional conversion methods

**Key Features**:
- ✅ Uses same yearMonth format as Room ("YYYY-MM")

#### **FirestoreUserSettings.kt**
- New data model for cloud-synced user preferences

**Key Features**:
- ✅ Replaces DataStore for cloud-synced settings

### 2. Firestore Repository (`data/firebase/FirestoreRepository.kt`)

Complete repository with CRUD operations for all data types.

#### **Collection Structure**
```
users/{userId}/
  ├── entries/{date}          // Daily entries (date as ID)
  ├── jobs/{jobId}            // Jobs (auto-generated IDs)
  ├── goals/{yearMonth}       // Monthly goals (yearMonth as ID)
  └── settings/preferences    // User settings (single document)
```

#### **Daily Entry Operations**
- ✅ `upsertEntry(entry)` - Create or update entry
- ✅ `getEntryByDate(date)` - Real-time Flow for single entry
- ✅ `getEntriesBetween(start, end)` - Real-time Flow for date range
- ✅ `getEntriesForMonth(yearMonth)` - Convenience method for monthly data
- ✅ `deleteEntry(date)` - Delete entry
- ✅ `batchUpsertEntries(entries)` - Batch write (max 500 per batch)

**Features**:
- Real-time updates via Firestore snapshots
- Automatic ordering by date (descending)
- Error handling with `Result<T>` pattern
- Logging for debugging

#### **Job Operations**
- ✅ `upsertJob(job)` - Create or update job, returns document ID
- ✅ `getAllJobs()` - Real-time Flow, ordered by name
- ✅ `getJobById(jobId)` - Fetch single job
- ✅ `deleteJob(jobId)` - Delete job

**Features**:
- Auto-generated document IDs for new jobs
- Alphabetical sorting

#### **Monthly Goal Operations**
- ✅ `upsertGoal(goal)` - Create or update goal
- ✅ `getGoalForMonth(yearMonth)` - Real-time Flow for specific month
- ✅ `getAllGoals()` - Real-time Flow, ordered by month (descending)

**Features**:
- Document ID equals yearMonth for predictable access
- Latest months first

#### **Settings Operations**
- ✅ `saveSettings(settings)` - Save user preferences
- ✅ `getSettings()` - Real-time Flow for settings

**Features**:
- Single document per user at fixed path
- Instant sync across devices

#### **Utility Operations**
- ✅ `getEntriesCount()` - Count total entries (for statistics)
- ✅ `isAuthenticated` - Check if user is logged in
- ✅ Error handling with detailed logging

## Firestore Security Rules (Deployed to Firebase Console)

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Users can only access their own data
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
      
      // All subcollections inherit the same rule
      match /{document=**} {
        allow read, write: if request.auth != null && request.auth.uid == userId;
      }
    }
  }
}
```

**Security Features**:
- ✅ User must be authenticated
- ✅ Users can only access their own documents
- ✅ Applies to all subcollections (entries, jobs, goals, settings)
- ✅ No cross-user data access possible

## Firestore Best Practices Implemented

### ✅ Document Structure
- User-centric design (`users/{userId}/...`)
- Predictable document IDs (date, yearMonth)
- Flat subcollections (avoid deep nesting)

### ✅ Security
- Row-level security (user can only access own data)
- Authentication required for all operations
- No public data exposure

### ✅ Performance
- Indexed queries (date range queries use date field index)
- Batch writes for bulk operations (500-item chunks)
- Real-time listeners only where needed

### ✅ Data Integrity
- Timestamps (`createdAt`, `updatedAt`)
- No-arg constructors for Firestore
- Type-safe data classes

### ✅ Error Handling
- Result<T> pattern for all operations
- Detailed logging (TAG = "FirestoreRepository")
- User-friendly error messages

## Troubleshooting

### Common Issues

**"User not authenticated" error**:
- Ensure you're logged in
- Check FirebaseAuth.getInstance().currentUser != null
- Restart app if session expired

**"Permission denied" error**:
- Verify Firestore rules are deployed
- Check user ID matches document path
- Confirm authentication token is valid

**Data not appearing in Console**:
- Wait a few seconds for Firestore to sync
- Refresh Console page
- Check correct project/database selected

**Real-time updates not working**:
- Verify Flow is being collected
- Check listener isn't being removed prematurely
- Ensure coroutine scope is active
